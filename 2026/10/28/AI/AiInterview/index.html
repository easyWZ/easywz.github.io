做一个AI模拟面试官项目

本文最后更新于 2026年10月30日 上午

1. 做的什么项目：

做一个Ai模拟面试官，页面一个输入框，输入岗位，点击发送按钮，ai会模拟面试官提问，输入回答后ai给出评价并进行下一题。

2. 技术搭建：

npm create vite@latest ai-interviewer -- --template react-ts

  1. node版本 我此时用的是 v24.21.0
  2. 因为 typescript-eslint 官方还不支持 TS7，降级 TypeScript 到 6.x
  3. 项目启动： yarn dev

3. 只实现输入岗位AI出题，跑通单轮对话

  1. 链接deepseek官网：https://platform.deepseek.com/api_keys，申请API key

  2. 项目根目录创建 .env.local , 内容里写入：VITE_DEEPSEEK_API_KEY=sk-xxxxxx ,sk-xxxxxx是申请的API key

    1. 注：生产环境应该走自己的后端代理，不能把 key 放前端

  3. 要让typescript识别环境变量，创建src/vite-env.d.ts：

    原理：

    1. 只有在文件最顶部、且以 /// 开头的单行注释，才会被当作“指令”去执行；这行代码的作用是：告诉 TypeScript 去加载 Vite 官方提供的类型声明文件。因为 Vite 不是原生的浏览器环境，它塞了一些特殊的环境变量（比如 import.meta.env）。如果不写这行，TypeScript 根本不知道什么是 import.meta.env，就会在编辑器里画红线报错。
    2. “vite/client” 其实指向的是 node_modules/vite/client.d.ts 这个文件。里面预先定义好了 import.meta.env.MODE、import.meta.env.BASE_URL 等等。
    3. 在下面声明了 ImportMetaEnv 接口，这其实是 TypeScript 的接口合并（Declaration Merging）特性：把自定义的 VITE_DEEPSEEK_API_KEY 补充到了 Vite 默认的类型定义里。

  6. 思考：

    1. 大模型应用开发最核心的本质：本质上就是在不断地“调接口”，把历史对话打包发过去，拿回一串文本。
    2. 在 chat 接口里，我们传给大模型的其实是一个消息数组（messages），里面包含三种角色（Role）：
      1. system（系统规则）：它是用来给 AI 设定人设、边界和输出格式的。比如“你是一名前端面试官”“你只能提问不能回答”“输出格式必须是 JSON”。最高优先级的指令。
      2. user（用户输入）：真实用户在页面上打字输入的内容。比如你粘贴的 JD（职位描述），或者你回答的面试题。
      3. assistant（AI 的回复）：大模型返回给你的内容。多轮对话时，你需要把 AI 之前说过的话也放进数组里，它才知道“自己上一句问了什么”。

4. 实现多轮对话

  1. 改造 services/ai.ts
  2. temperature: 0.7 ：
    1. 采样温度，取值范围 0 到 2，默认值是 1.0（基于deepseek，各ai的参数与值范围不一样，但是意义是一样的）
    2. 值越低（接近 0）：输出越确定、越保守。同一个问题问很多遍，回答基本一样。适合代码生成、数学解题、事实问答
    3. 值越高（接近 2）：输出越随机、越有创意。适合写诗、头脑风暴。
  3. stream: false
    1. 控制响应方式
    2. stream: false ：AI 把一整段回答全部生成完之后，才一次性返回。用户会先看到“面试官正在思考中…”，然后突然出现完整的一段话。
    3. stream: true：AI 每生成一小段就立刻推给前端，前端可以逐字渲染。这就是平时用 ChatGPT 看到的打字机效果，体验会好很多。
    4. 设置 stream: true 之后，需要用 ReadableStream 去读取响应体，而不是 await response.json()。
  4. 其余参数：
    1. max_tokens 限制 AI 最多生成多少 token
    2. stop 遇到指定词就停止生成
